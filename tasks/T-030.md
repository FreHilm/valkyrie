## Goal

Port `GameMenu.cs`: the in-quest menu offering undo, save and a return to the
main menu.

## Acceptance Criteria

- [x] A menu reachable during play without disturbing the board behind it
- [x] Undo restores the previous state from the undo stack
- [x] Save writes the current quest to a slot
- [x] Returning to the main menu autosaves on the way out, as `GameMenu.Quit` does
- [x] The editor entry is omitted until T-019 lands

## Notes

Depends on T-026 — undo and save both need the serialiser that does not exist
yet.

The C# reaches this from `MenuButton`, which is drawn alongside the phase bar.

## Progress

- 2026-08-28: Found while auditing the play loop against the C#.

- 2026-08-28: The AC about asking before leaving was wrong, and the C# says so:
  `GameMenu.Quit` calls `SaveManager.Save(0, true)` — it writes the autosave on
  the way out, so leaving is not the same as losing the game and a confirmation
  would be protecting against something that cannot happen. Changed to match.

  The menu stays reachable while a dialog is up, which the phase bar's Items
  and Set deliberately are not: this is how a player saves and how they leave,
  and neither should wait for an event to be answered.

  Undo is disabled rather than hidden at the start of a quest, so the entries
  below it do not move under the pointer once there is something to step back
  to.

  This also gives the save-select screen its writing entry point, which is what
  T-026 left without one.
