## Goal

Stand up the TypeScript workspace the port lives in, with tests and CI wired from the first
commit, so every subsequent porting task lands against a working harness.

## Acceptance Criteria

- [x] Monorepo with a clear package split: core logic, platform/IO, UI, importer tooling
- [x] The core package has no dependency on any browser or Node API — it must be testable in isolation
- [x] Test runner in place and running in CI
- [x] Lint and format enforced, mirroring the intent of the existing `.editorconfig`
- [x] CI runs on PR alongside the existing Unity workflows without interfering with them
- [x] `README` explains how to build and test the web port

## Notes

Keep the web port in this repository rather than a fork, so the Unity implementation stays
available as the reference during porting and the 893 existing tests stay side by side with
their TypeScript counterparts.

The core package boundary matters more than the tooling choice. The reason the port is viable
at all is that ~13k LOC of this codebase is engine-free; the package layout should make
violating that boundary an error rather than a habit.

## Progress

### 2026-08-25

Workspace stood up at `webapp/` (not `web/`, which is the existing GitHub Pages
site).

- npm workspaces + TypeScript project references + vitest.
- `packages/core` created. The no-host-API rule is enforced mechanically rather
  than by convention: the package compiles with `"lib": ["ES2022"]` and
  `"types": []`, so a stray `document` or `fs` reference fails the build.
- Only `packages/core` exists so far. The platform, UI and importer packages
  are deliberately not scaffolded — their shape depends on T-003, T-011 and
  T-016, and empty directories would just be guesses.
- `.github/workflows/webPort.yml` added. Path-filtered to `webapp/**` so it
  cannot interfere with the Unity workflows. Two jobs: typecheck + tests with
  coverage thresholds, and the differential harness from T-005.
- `webapp/README.md` documents commands, the core-package boundary, and the
  porting loop.

Strict TS options on from the start (`noUncheckedIndexedAccess`,
`exactOptionalPropertyTypes`, `verbatimModuleSyntax`) — cheap now, expensive to
retrofit across 40k LOC later.

ESLint (typed, via typescript-eslint) and Prettier configured and clean. Added
a `[*.{ts,mts,js,mjs}] indent_size = 2` block to the root `.editorconfig`,
which had no TypeScript rule — the `[*]` default of 4 does not match TS
convention, and JSON/YAML there are already 2.

**Dependency on T-003 removed.** This task was started ahead of the ADR
deliberately: the decisions T-003 still owns (rendering, board strategy, where
the importer runs, texture format, persistence) do not touch the workspace
layout, the test harness, or the core package boundary. T-003 still gates
T-016 and the rendering work. If it later reverses a tooling choice made here,
the cost is small and confined to config.
