## Goal

Read the content current FFG builds download at runtime, rather than only what
ships inside the install.

Found while verifying T-014 against a real Mansions of Madness 2.1.6 install:
**the install no longer contains the game text or the scenarios.** They are
downloaded on first run and cached outside it — on macOS,
`~/Library/Caches/com.fantasyflightgames.mom`, 413 MB across 38 UnityFS
AssetBundles.

Without this, an import of a current MoM build yields images and audio but no
`ffg` dictionary, and MoM base content references **3,725 distinct `{ffg:…}`
keys** — so the game renders as raw keys. This is a prerequisite for the
MoM-first play loop chosen for T-018.

The shipped Valkyrie importer has the same gap: `FetchContent` reads the
install only and cannot open bundles.

## Acceptance Criteria

- [x] `UnityFS` container reader: header, block list, directory, yielding the
      inner `SerializedFile` for the existing reader
- [x] Cache directory located per platform, alongside the install
      (`AppFinder` has a `DataPath` concept, currently Android-only)
- [x] `Localization_*` TextAssets extracted into `{import}/text`, so the `ffg`
      dictionary builds
- [x] Scenario and DLC bundles read as well as the language bundles
- [x] Verified differentially against AssetStudio, as the other readers are
- [ ] Behaves sensibly when the cache is absent — a fresh install that has not
      been run yet has no downloaded content, and that should be reported
      clearly rather than producing a half-import

## Notes

Measured, so the scope is known rather than guessed:

- all 38 bundles are **version 8 and uncompressed** (`flags 0xc0`), so no LZ4
  or LZMA decompressor is needed;
- AssetStudio's own `BundleFile.cs` is 367 lines and covers every case; the
  uncompressed path is a fraction of that;
- the inner files are ordinary `SerializedFile`s that the T-014 reader already
  handles — verified by pointing the C# probe at the cache, which read 189
  asset files and found 321 TextAssets including `Localization_en` (1.1 MB,
  6,791 lines, `KEY,English` format).

Compression support will be needed eventually — other titles and other
versions do compress their bundles — but nothing here requires it, so it should
not be built speculatively.

Worth checking whether D2E does the same thing before assuming this is
MoM-specific.

## Progress

**2026-08-25 — done. The `ffg` dictionary now builds: 3,723 of the 3,725 keys
MoM base content needs resolve.**

`packages/platform/src/unityBundle.ts` reads the `UnityFS` container,
`lz4.ts` decompresses the storage blocks, and `ffgImport.ts` expands a bundle
into the SerializedFiles inside it so the existing reader handles them
unchanged. 18 new tests.

**Verified against AssetStudio over the real cache: 916 of 916 objects
byte-identical** — through LZ4, the container, the reader and the payload
hashes. Mutation-tested: a wrong LZ4 match-length bias, a bulk copy in place of
the overlapping one, dropped extended-length runs and a missing header
alignment each broke 887-916 of the 916.

**One measurement I got wrong first time**, and it is worth recording. I read
the archive header's `flags 0xc0` as "uncompressed" and wrote the task on that
basis. That field describes the *block list*, not the block *data*: the storage
blocks are **LZ4**, 5,373 of them against 770 uncompressed. The reader's own
error message caught it — it named LZ4 rather than producing garbage — and the
scope grew by one ~50-line decompressor.

**Two other bugs this corpus exposed in the T-014 reader**, neither reachable
from the install alone:

- Path IDs were range-checked as if they were file offsets. In an AssetBundle
  they are 64-bit hashes that routinely exceed `Number.MAX_SAFE_INTEGER`, so
  every bundle failed. `pathId` is now a `bigint`.
- The same check was applied to `localIdentifierInFile` in the script-types
  table, which is also an identifier rather than an offset.

Install files use small sequential path IDs, so neither could have surfaced
before a licensed install's downloaded cache was available.

**Two keys still do not resolve**: `MONSTER_HUNTING_DEEP_ONE_ATTACK_2` and
`MONSTER_HUNTING_DEEP_ONE_MOVE_2`. They are absent from every language file in
MoM 2.1.6, so this is Valkyrie content that has drifted from the app — the
Unity build would render those two lines as raw keys too.

**A full import now reads install and cache together**: 1,146 textures, 245
audio, 350 text, 289.2 MB in 117s.

**Not met — offline behaviour when the cache is absent.** A fresh install that
has never been run has no downloaded content, and the import currently just
finds less rather than saying so. It should report that clearly; left
unchecked rather than claimed.

**Also outstanding: 99 audio streams skipped**, all because their Vorbis setup
header is not one of the three `OggVorbisHeader.cs` carries — mostly scenario
voice-over. Same limit the Unity build has, except it writes an undecodable
file instead of reporting it.

**D2E is unverified.** `CONTENT_CACHE` has D2E paths, but no D2E install has
been read.
