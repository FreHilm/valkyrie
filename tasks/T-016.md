## Goal

Build the web UI foundation that replaces `UIElement.cs` (683 lines), `UIScaler`,
`UIWindowSelectionList*` and the rest of `unity/Assets/Scripts/UI`. This is rewrite territory,
not porting — 36 of 37 files in that folder are uGUI-bound.

## Acceptance Criteria

- [x] Component set covering what the screens need: panels, buttons, scrolling lists, modal dialogs, text with the project's fonts
- [x] Equivalent of `UIScaler` — the current UI is laid out in scaled units against screen size,
      and the port needs a coherent responsive story that replaces it
- [x] Selection list with trait filtering, matching `UIWindowSelectionListTraits.cs` (668 lines)
- [x] Localized text throughout, using the T-006 runtime — no hardcoded UI strings
- [x] Keyboard and pointer input; touch targets sized for mobile
- [x] Baseline accessibility: focus order, contrast, screen-reader labels on controls
- [x] Works at both desktop and phone viewport sizes

## Notes

Do not transliterate `UIElement`. It is an imperative wrapper over `GameObject` + `RectTransform`
that exists because uGUI has no declarative layer; the DOM already provides what it was
approximating. A direct port would import the awkwardness for no benefit.

This is also the natural place to fix the localization discipline. `.agent/rules/text-localization.md`
already forbids hardcoded UI strings; building the components so an unlocalized string is
awkward to write makes the rule self-enforcing.

Fonts live in `unity/Assets/Resources/Fonts/` and are currently rendered via TextMeshPro.
Web fonts replace that directly, but check licensing for web embedding before shipping.

## Progress

**2026-08-25 — done.** New package `@valkyrie/ui`; 58 tests, plus a ninth
differential harness.

**Built under the ADR's own recommendations** (T-003), which you have not
signed off yet. Nothing here depends on the two that are still open: the board
renderer is T-017, and no bundler is needed until there is an app package.

**Two things ported, everything else rewritten.** The notes are right that
`UIElement` should not be transliterated. What was genuinely ported is the
*unit system* (so ported screens can use the same numbers) and the *trait
filtering* (because its semantics are load-bearing and subtle).

**The trait filtering is verified against the original.**
`tools/differential/traits` extracts `SelectionItemTraits` and `TraitGroup`
from the uGUI-bound source by brace-matching, compiles them with the project's
own `LinqUtil` and a stub for the translated SOURCE string, and compares:
**0 divergences across 4 seeds x 3,015 cases**. Mutation-tested — four
deliberate bugs, all caught, 16-62 diverging cases each.

Two findings from it worth keeping:

- The **"Source" group filters differently from every other group**, and
  which group that is depends on the *translated* word — so filtering
  behaviour changes with the user's language. Reproduced exactly.
- `TraitGroup.AddTraits` indexes `GetTraits()[_name]` unguarded and would throw
  for an item with no trait in that group. It never fires in the app, but only
  because of the order `Draw()` calls things in. The harness reproduces that
  sequence and the port documents why it matters.

**Unit system**: `UIScaler`'s own comment states the expected numbers ("30
units high, 40 across at 4:3, 53.33 at 16:9"), and the tests assert them
directly. Two deviations: it follows window resizes, which the C# explicitly
gives up on; and a 14px floor per unit, because 1/30th of a phone's height puts
small text near 5px.

**Localization is enforced by the API rather than by review.** Components take
a `Text`, never a bare string. `rawText()` exists for content that is data
rather than interface copy and is named so that misusing it stands out. Writing
an unlocalized label is now awkward, which is what makes
`.agent/rules/text-localization.md` self-enforcing.

**Accessibility the Unity UI does not have**, and asserted in tests: real
`<button>`s; selectable lists as a listbox with roving tabindex, arrow-key
focus movement and Enter/Space selection; `<dialog>` with `showModal()` for
free focus trapping — and a dialog with no close route refuses Escape rather
than being dismissible by a path its UI does not offer; labelled regions; a
real `<label for>` on the search box; an `aria-live` result count; and touch
targets of `max(1.6 units, 44px)`, since the unit floor alone can fall below a
hittable size.

**One design change from the C#:** a trait filter is one button cycling
neutral -> required -> excluded, rather than two click targets distinguished by
colour alone. Fewer targets on a phone, and the state is readable without
colour.

**Left unresolved, deliberately: the fonts.** `ColumbusMT`,
`Gara_Scenario_Desc` and the Descent symbol font are commercial faces whose
licences do not obviously cover web embedding — which the notes flag. They are
named in the CSS behind generic fallbacks and **not bundled**. Confirm the
licences before adding any `@font-face`. Until then the UI renders in the
fallback stack: a visual difference from the Unity build, not a functional one.

Full suite: 1,048 tests, lint/format/typecheck clean, all nine differential
harnesses at 0 divergences, size budget green (`@valkyrie/ui` 9.1 kB gzipped).
