## Goal

Port `libraries/ValkyrieTools/IniRead.cs` (308 lines) and `unity/Assets/Scripts/ConfigFile.cs`.
The INI parser is the foundation of the whole content model — quests, content packs, saves and
config are all INI — so it goes first and must be exactly faithful.

## Acceptance Criteria

- [x] `IniRead` ported with identical behaviour, including its handling of duplicate keys,
      comments, quoting and section semantics
- [x] `ConfigFile` ported on top of it
- [x] All cases from `IniReadTests.cs` and `ConfigFileTests.cs` pass against the TypeScript version
- [x] Round-trip verified against a corpus of real `quest.ini` files from published scenarios
- [x] Locale-independent number parsing — the existing rule requires `CultureInfo.InvariantCulture`
      everywhere, and JS `parseFloat` has its own edge cases to pin down

## Notes

Fidelity beats elegance here. Community scenarios in the wild depend on the current parser's
exact quirks, including ones that look like bugs. Any deliberate deviation needs to be recorded
in the ADR, not decided ad hoc.

## Progress

### 2026-08-25

Ported and verified. 82 tests, 100% statement/branch/function/line coverage on
every source file.

**Verification was differential, not assumed.** A harness compiles the
unmodified `IniRead.cs` (stubbing only `ValkyrieDebug`, which pulls in
UnityEngine) and diffs it against the port structurally — section order, key
order, values, thrown exceptions. Reproducible via
`webapp/tools/differential/run.sh`, and wired into CI.

| Corpus | Cases | Real divergences |
| --- | ---: | ---: |
| Hand-written edge cases | 59 | 0 |
| Fuzz | 12,000 | 0 |
| Every shipped `.ini` (236 files, 719 KB) | 472 | 0 |
| Number parsing | 31,073 | 0 |

This mattered. The hand-written tests passed on the first run — which only
proved they encoded my *reading* of the C#. The fuzz corpus then found three
genuine bugs in my `AllowThousands` handling (`"5,"`, `"1,2,3"`, `"+NaN"`).
Later port tasks should not trust hand-written tests alone.

**Two deviations, both cases where the C# throws** (see
`webapp/docs/ini-port-deviations.md`):

1. A whitespace-only line crashes `IniRead` with `IndexOutOfRangeException` —
   `l.Trim()[0]` is guarded only by `l.Length > 0`, and `RemoveEmptyEntries`
   does not drop whitespace-only lines. **One line of spaces aborts the load of
   that file.** No shipped content hits it today. The port skips such lines.
2. The section-reader overload throws `ArgumentException` on a repeated
   valueless key. The port makes it first-wins, like every other duplicate.

**A real shipped bug found and fixed in the port.** `Audio.cs:25`, `:37`,
`OptionsScreen.cs:228`, `:286` and `Game.cs:218` call
`float.TryParse(s, out v)` with the *current* culture, paired with
`value.ToString()` on the write side. Measured against .NET:

| Culture | `TryParse("0.5")` | `(0.5f).ToString()` |
| --- | --- | --- |
| en-US | true, 0.5 | "0.5" |
| de-DE | true, **5** | "0,5" |
| sv-SE / fr-FR | **false, 0** | "0,5" |

So a config written on an English machine gives **silently muted audio** on a
Swedish or French one (the `vSet.Length == 0` fallback does not fire, because
the string is not empty), and **10x volume** on German. Config files are not
portable between locales. `parse.ts` parses and formats invariantly.

Worth fixing in the Unity build too — it is a five-line change and affects
current users.

**Scope note:** `IniRead.ReadFromIni` (the file-reading entry points) are not
ported; they belong to the platform layer. `ConfigFile` likewise does not read
or write `config.ini` — the C# does both synchronously in its constructor and
`Save()`, but the web storage layer is asynchronous and inventing a sync file
contract here would prejudge T-011. The class owns the data and reports
changes; the host persists.

Also pinned, because it would have been silently wrong: .NET uses **different
whitespace sets** for numbers and booleans, and neither matches JS `.trim()`.
`"5\u00A0"` is rejected as a number but `"true\u00A0"` parses as a boolean, so
trimming with `.trim()` before parsing a number would wrongly accept it.
