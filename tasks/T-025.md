## Goal

Show `endGame` when a scenario sets `$end`. The screen is ported and reachable
from the debug menu, but a real quest that ends leaves the player on a blank
board.

## Acceptance Criteria

- [ ] A quest reaching `questHasEnded` presents the end-of-quest screen
- [ ] It carries the scenario name, the party, the events played, and the elapsed rounds and time
- [ ] Returning to the main menu from it tears the session down cleanly
- [ ] No feedback form is built — the C# posts answers to a Google Form this fork does not use
- [ ] Verified in a browser on a scenario driven to its end

## Notes

`playScreen` handles `kind === 'ended'` by clearing the overlay and the phase
bar and returning. Nothing above it notices, so the quest simply stops being
drawn. `endGame` is currently only called from `endGameDemo` in `main.ts`.

`Quest.eventList` — the events the player answered — is what the screen lists;
check the port records it, because the C# appends to it in
`DialogWindow.onButton` alongside the log entry.
