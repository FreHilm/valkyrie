## Goal

Show `endGame` when a scenario sets `$end`. The screen is ported and reachable
from the debug menu, but a real quest that ends leaves the player on a blank
board.

## Acceptance Criteria

- [x] A quest reaching `questHasEnded` presents the end-of-quest screen
- [x] It carries the scenario name, the party, the events played, and the elapsed rounds and time
- [x] Returning to the main menu from it tears the session down cleanly
- [x] No feedback form is built — the C# posts answers to a Google Form this fork does not use
- [x] Verified in a browser on a scenario driven to its end

## Notes

`playScreen` handles `kind === 'ended'` by clearing the overlay and the phase
bar and returning. Nothing above it notices, so the quest simply stops being
drawn. `endGame` is currently only called from `endGameDemo` in `main.ts`.

`Quest.eventList` — the events the player answered — is what the screen lists;
check the port records it, because the C# appends to it in
`DialogWindow.onButton` alongside the log entry.

## Progress

- 2026-08-28: Found while auditing the play loop against the C#.

- 2026-08-28: `playScreen` gained an `onEnded` handover, the same shape as
  `onChangeQuest` — the summary needs the party's names and how long they
  played, none of which the play screen has. It fires once however often the
  board redraws, or the summary would be rebuilt under the player.

  `Quest.eventList` was already recorded (`EventManager.history`) and `#round`
  was already a variable; the clock was not kept anywhere. `Quest.start_time`
  lives on the quest in the C# so a save can carry the running total, but the
  session here is deterministic and reading a clock inside it would make a
  replay depend on when it ran — so `startedAt` sits in the screen that plays,
  and moves onto the quest when saves land (T-026).

  DEVIATION, recorded in the code: `EventManager.cs:466` sends a scenario that
  is not a downloaded package straight to the main menu, so an author testing
  one is not asked to rate it — that rating went to a stats endpoint. This port
  sends nothing anywhere, so there is nothing to spare a test scenario from and
  every quest gets its summary.

  Verified in Chrome on a scratch scenario that sets `$end`: the board comes
  down and the summary reads "End Probe / Agatha Crane, Carson Sinclair /
  Rounds 0 / 0 min / Events seen 2", and "Main menu" returns cleanly. The first
  attempt threw `Cannot close a closed AudioContext` — `show` already runs the
  previous screen's `onLeave`, so the teardown I had written was a second one.
