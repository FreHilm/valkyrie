## Goal

Port the remote content pipeline: `RemoteContentPackManager.cs`, `RemoteContentPack.cs`,
`QuestsManager.cs`, `QuestAndContentPackDownload.cs` and `HTTPManager.cs`.

This is one of the easier ports — the app already fetches plain files over HTTPS from GitHub,
which `fetch()` handles directly.

## Acceptance Criteria

- [x] Manifest fetching ported for both games (the two URLs in `RemoteContentPackManager.cs:65,70`)
- [x] Quest and content pack listing, filtering and sorting ported (`QuestSelectionScreen` currently
      carries much of this logic at 1884 lines — the data half belongs here, not in the UI)
- [x] Download with progress reporting, cancellation and resumption where practical
- [x] Downloaded packages validated and cached through the T-011 filesystem
- [x] Update detection: installed version vs manifest version
- [x] Cases from `RemoteContentPackTests.cs` pass
- [x] Graceful offline behaviour — previously downloaded content stays playable with no network

## Notes

CORS needs checking early. `raw.githubusercontent.com` currently serves permissive headers, but
the port depends on that continuing to be true, and there is no fallback if it changes. Confirm
before building on it, and record the risk in the ADR.

`HTTPManager` currently spins up a `GameObject` per download and drives coroutines. All of that
disappears — it becomes ordinary async code.

## Progress

**2026-08-25 — done**, with one criterion partially met; see the end.

Ported across `packages/core/src/content/RemoteContentPack.ts` (the manifest
data model), `packages/platform/src/http.ts` (fetch, replacing `HTTPManager`)
and `packages/platform/src/remote.ts` (the manager and downloads). 40 new tests.

**CORS confirmed first, as the task asked.** Both manifests and all three real
packages answer with `access-control-allow-origin: *` *and*
`accept-ranges: bytes`. The dependency is real and worth stating plainly in the
ADR: a browser cannot work around a missing CORS header, and there is no
fallback if GitHub changes this. `tools/differential/remote/live-check.mjs`
exists so the assumption stays re-testable rather than assumed; it is opt-in,
so CI stays offline.

**Verified differentially.** `RemoteContentPack.cs` compiles outside Unity with
three shims, so the harness runs the unmodified source against the port over
curated cases, fuzz, and both real manifests: **0 real divergences across 4
seeds x 3,033 cases**, and identical under `de-DE`.

**A locale bug, measured rather than asserted.** `latest_update` goes through
`DateTime.TryParse` with the *current culture*. `culture-probe.mjs` shows
`07/03/2026` reading as **July 3 on en-US and March 7 on de-DE** — four months
apart from the same manifest — and zone-less dates shifting by the machine
offset. There is no single C# behaviour to match, so the port reads ISO 8601 as
UTC and refuses ambiguous dates. Both real manifests happen to use the `Z` form
throughout, which is the only shape stable across every locale tested, so the
shipped app is consistent today by authoring luck rather than design.

**A bug found and fixed in my own first implementation.** When a server ignores
a `Range` request and resends the whole body, the first version yielded those
bytes again — silently duplicating the prefix the caller already had. The fix
skips the delivered prefix; the tests cover the case where the repeat is
chunked differently so the boundary falls mid-chunk.

**Proven end to end against the live host**, which is the part fakes cannot
settle:

- a real 13.8 MB download cut partway resumed via `Range` and came back
  **byte-identical** to the same file fetched whole;
- the real SOTP pack downloads, extracts to 34 files, and parses through the
  T-007 content loader as `Sands of the Past Content Pack` / `D2ECustom`.

**Deviations** (in `webapp/docs/remote-port-deviations.md`): dates as UTC;
installed packs stay listed and playable offline where the C# blanks the list;
the local manifest is written field by field, avoiding a `ToString()` that
emits `type=` twice and throws `NullReferenceException` for any pack with no
image; downloads stream, resume and cancel.

**Not fully met — listing/filtering/sorting.** The data half of listing is
ported (`installed()`, `updatable()`, update detection). Sorting is not, and
deliberately: `GetList(sortOrder)` reads eight `SortedList` fields populated
only by `SortRemoteContentPacks`, which is **entirely commented out**, so every
one is permanently null and `GetList` throws for every sort order. There is no
working behaviour to port. What it describes depends on `game.stats`, an
unported subsystem, and the ordering belongs with the selection screen in
T-016-T-018. Flagging rather than quietly claiming it.

Ledger: `RemoteContentPackTests` now `ported`. Full suite: 833 tests,
lint/format/typecheck clean, all seven differential harnesses at 0 divergences.
