## Goal

Make the board's pieces reachable without a pointer. It is a canvas with
pointer hit-testing and nothing else, so tiles, tokens and monsters cannot be
reached by keyboard or announced by a screen reader.

## Acceptance Criteria

- [x] Every board item is focusable in a sensible order and activates with Enter or Space
- [x] Each announces what it is, as the monster strip's icons already do
- [x] Panning and zooming stay available from the keyboard
- [x] The canvas keeps its current pointer behaviour unchanged
- [x] Tests covering focus order and activation

## Notes

Out of step with the rest of the port, which uses real `<button>` elements and
labels everywhere precisely so the platform provides this. `board.ts` maps a
pointer position to an item through `hitTest` and has no DOM node per item;
`onKeyDown` currently handles the viewport only.

An off-screen list of buttons mirroring the scene is probably enough — it needs
to reach the same `onSelect` the canvas does.

## Progress

- 2026-08-28: Found while auditing the play loop against the C#.

- 2026-08-28: The board mirrors its pieces into an off-screen list of real
  `<button>`s beside the canvas. Using a button rather than anything cleverer
  is the whole trick: focus, the accessible name, and Enter or Space to
  activate all come from the platform, and pressing one reaches the same
  `onSelect` a click does. Panning and zooming were already on the canvas's own
  `keydown` and needed nothing.

  Leaving scenery out turned up a real bug. Tiles were hit-tested like
  everything else, so a click on bare floor queued an event named after the
  tile and wrote "Warning: Missing event called: TileFoyer" into the quest log.
  The C# never had this: it keeps tiles on their own canvas, and only the token
  and monster canvases take clicks. Board items say whether they are
  interactive now, and both the pointer and the list respect it.

  Some existing play-screen tests counted every button on the screen and now
  saw the board's as well. They were loosely scoped rather than wrong, so they
  now say which buttons they mean.

  Verified in Chrome on Exotic Material: the list holds the two tokens and no
  tiles, and focusing one and pressing Enter opens its event.
