## Goal

Fill the remaining `onLog` hooks so the quest log records combat, not just
event prose.

## Acceptance Criteria

- [x] A monster activation logs its text, master actions and move (`ActivateDialogMoM.cs:35,80,116`)
- [x] An attack logs its text (`InvestigatorAttack.cs:69`)
- [x] An evade logs its text (`InvestigatorEvade.cs:49`)
- [x] A horror check logs its text (`HorrorCheck.cs:65`)
- [x] Newlines escaped on the way in, as the other entries are
- [x] Tests that fail if any one of them stops being written

## Notes

`play.ts` passes `onLog: () => {}` to both `monsterDialog` and
`activationDialog` — the hooks are there and do nothing. Event text is logged
as of the phase-bar work; this is the rest of what a player would expect to
read back.

## Progress

- 2026-08-28: Found while auditing the play loop against the C#.

- 2026-08-28: Smaller than it looked. Both dialogs already produced the entries
  and escaped their newlines — `monsterDialog.showText` for attack, evade and
  horror, `activationDialog.logOnce` for the effect, master actions and move —
  and `play.ts` passed `onLog: () => {}` to each, so every one was handed over
  and thrown away. The work was a `QuestSession.logEntry` for them to reach and
  two stubs replaced.

  It records a player entry rather than an editor one, which matters: an editor
  entry is hidden unless the developer view is open, so logging combat that way
  would have looked like it still did not work.

  Noticed while fixing: `tsc -p packages/ui` only covers `src/**`, so the test
  harness had been missing `pressQuota` since T-027 without anything
  complaining. Only the runtime failure here surfaced it.
