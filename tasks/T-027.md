## Goal

Apply `quota` and `quotaVar`, which gate a repeatable event so it takes more
than one attempt. Both are parsed onto `QuestEvent` and never read.

## Acceptance Criteria

- [x] An event with `quota` completes only once its attempt count reaches the quota
- [x] `quotaVar` reads the quota from a variable and writes the running count back
- [x] The count is per event section, as `Quest.eventQuota` keys it
- [x] The dialog shows progress toward the quota, as `DialogWindow` does
- [x] Cases covered by tests that fail without the gate

## Notes

This is the "search this room, three attempts" mechanic. Without it those
events complete on the first press, which changes a scenario's pacing and can
hand out its rewards far too early.

Used by 6 of the 7 MoM scenarios in the library: 2230h At The Bird's Pet Shop,
Exotic Material, In Places Unseen, The Fall of House Lynch, The Robbery of the
Kadakian Idol, and The Truth.

`DialogWindow.cs:48` reads it, `:259` writes `quotaVar` back, and `:274`
decides whether the event is finished.

## Progress

- 2026-08-28: Found while auditing the play loop against the C#.

- 2026-08-28: The task described this as "needs more than one attempt", which
  is not what it is. `DialogWindow.CreateQuotaWindow` draws a `-` / value / `+`
  spinner from 0 to 10 and exactly one button — `GetButtons()[0]`, whatever the
  event declares — and what the player dials is what the event acts on. Two
  modes, both now implemented:

  - `quota=<number>`: the dialled figure is added to a per-section tally
    (`Quest.eventQuota`). Reaching the quota drops the tally and takes the
    first button; falling short takes the *second*, which is where a scenario
    writes "you found nothing this time". That second button is the reason the
    spinner only ever draws one.
  - `quota=<variable>`: the figure is written to that variable and the first
    button is taken. The spinner opens on the variable's current value, so
    "how many clues do you hold?" starts from what the quest already knows.

  Verified in Chrome on a scratch scenario carrying both: dialling 2 against a
  quota of 3 returned to the menu, a second 2 crossed it and reached the "found
  the key" event, and a `$clues` counter set to 4 reopened on 4.

  Seven mutations checked, six bit. The seventh showed a range clamp in
  `pressQuota` was unreachable — the spinner is the only caller and it cannot
  leave 0..10, which is why the C# does not clamp either — so it was removed.
